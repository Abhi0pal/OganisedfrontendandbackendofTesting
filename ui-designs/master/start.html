⚙ Dynamic Master Management

Har project ka data alag hota hai — SWCS ke liye District, Parivesh ke liye Category, MP Urban ke liye Ward. Yeh system allow karta hai ki bina code likhe naye masters define karo, unke columns configure karo, aur data fill karo.

📦
Master Definition
Master ka blueprint — naam, code, icon, tenant, system flag. Jaise "District Master" ya "Category Master".

📐
Column Definition

Table 2: master_column_definition

Table 3: master_data

📋 Step-by-Step Setup Sequence
1
📦 Master Definition — Kaun sa Master chahiye?
Sirf naam, code, icon, aur tenant batao. Structure baad mein banegi.
System Masters pre-loaded Open Page →
Why first? Master ka container banana padega pehle — jaise folder banate hain files daalne se pahele. Bina definition ke columns aur data ka koi ghar nahi.
Real Examples 🌍 Country — global, system=true, pre-loaded
🗺 State — global, system=true, 36 states
🏘 District — global, system=true, 750 districts
📂 Category — SWCS-specific, tenant=SWCS
🏙 Ward Master — MP Urban-specific
Key Fields name code (UNIQUE) tenant_id is_system allow_import display_order

📐 Column Definition — Kaun se fields honge?
Har master ke liye columns define karo — type, required, searchable, reference, validation.
Required before data entry Open Page →
Why second? Columns se pata chalta hai ki JSONB data mein kaun se keys honge. Bina columns ke form nahi banta, validation nahi hogi, aur reference links set nahi honge.
District Master Columns 🔑 id — NUMBER, system
📝 name — TEXT, required, searchable
🔤 code — TEXT, required, unique
🗺 state_id — SELECT, source: STATE master
📍 division_id — SELECT, source: DIVISION master
Key Fields column_key data_type is_required is_searchable options (JSONB) validation
3
🗄 Master Data — Actual rows fill karo
Column definitions ke basis par dynamically generated form ya CSV import se data add karo.
Data without columns not possible Open Page →
Why third? Pahele container (definition) aur blueprint (columns) taiyar ho. Ab actual geography ya category data fill karo. JSONB mein dynamic store hota hai isliye schema change nahi hota.

🔗 Data References — Auto-generated relationships
Jab state_id fill hota hai, Dehradun → Uttarakhand reference automatic ban jata hai. Yahan verify karo.
Auto-created on data save Open Page →
Why track references? Cascading dropdowns ke liye — District dropdown mein sirf Uttarakhand ke districts dikhane ke liye state_id ka reference chahiye. master_data_reference table yeh fast lookup enable karta hai.
